# Pre-registration switch-v1: switch to the transfer model when the visible shift g is abnormal. Written 30.10.2026 ~00:26 IST, before running.
Rule (from theory, no free constant tuned on results): g = 100 * L1 distance between the previous-election vote shares of the counted boxes (weighted by previous valid votes) and of all boxes. It uses only previous-election data, so it is observable live.
Null from theory: if the counted boxes were a random sample, g follows the permutation distribution of the same number of boxes drawn at random. Threshold = 95th percentile of g over 200 random draws of the same number of boxes (seed fixed 12345) from the same frame. This uses no election-night result.
Decision: g above the threshold -> use transfer_k002 (frozen method-v2 transfer model); else use base (ridge projection of method-v2).
Test: pooled share MAE (pp) and seats-out-of-place for switch vs always-base vs always-transfer, per order (random, low_likud_first, small_first, low_turnout_first) at 1/5/20/40% counted. Development T=23..26 (transfer needs T>=23 in the frozen code), holdout T=20,21 (T=19 has no previous pair for the transfer model). Reported separately.
Success rule (fixed now): switch is adopted only if, pooled over orders, it is no worse than base by more than 5% in random order AND better than base by >=20% in low_likud_first at 5% counted, on BOTH development and holdout. Otherwise "not adopted". Also report how often it switches in random order (false alarm rate; theory says about 5%).
